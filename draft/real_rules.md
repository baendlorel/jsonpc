# JSONPC (JSON with Property Comments) 真正规则总结

基于源代码分析的实际规则文档

## 1. 注释语法规则

### 1.1 注释格式
- **只支持行注释**：`// 注释内容`
- **不支持块注释**：`/* */` 格式不支持
- **注释独占一行**：注释必须单独占一行，不能与其他内容同行
- **注释前缀**：使用 `//` 前缀，存储时会自动去除前缀和后续空格

### 1.2 注释位置规则
- **属性级注释**：注释必须直接出现在属性名的正上方，中间不能有其他内容
- **文件级注释**：文件顶部和底部的注释会被特殊处理
- **注释识别**：注释行必须以 `//` 开头且该行只包含注释内容

## 2. JSON格式规则

### 2.1 基本格式
- **标准JSON语法**：除注释外，必须符合标准JSON语法
- **尾随逗号支持**：支持在对象和数组的最后一个元素后添加逗号
- **自动去除尾随逗号**：解析时会自动去除尾随逗号
- **字符串内无注释**：字符串字面量内部不支持注释

### 2.2 格式约束
```json
{
  // 这是允许的 - 属性注释
  "property": "value"
  // 这是不允许的 - 不能在其他位置
}
```

## 3. 注释存储和处理规则

### 3.1 内部存储结构
- **PathMap**：使用 `PathMap` 类存储注释映射
- **路径格式**：`property path (string[]) → comment content lines (string[])`
- **无前缀存储**：注释内容存储时不包含 `//` 前缀

### 3.2 解析流程
1. **预处理**：去除空白行和空行，规范化文本
2. **文件级注释**：提取顶部和底部注释
3. **UUID标记**：为有注释的属性生成UUID临时名称
4. **JSON解析**：解析标记后的JSON文本
5. **注释映射**：遍历解析结果，建立UUID与原始名称的映射
6. **数据清理**：从数据中删除UUID临时属性

### 3.3 序列化流程
1. **文件级注释**：先输出顶部注释
2. **深度遍历**：递归遍历数据结构
3. **注释插入**：在属性前插入对应的注释
4. **格式化输出**：保持一致的缩进和格式
5. **底部注释**：最后输出底部注释

## 4. 数组操作规则

### 4.1 支持的数组方法
- `push`：添加元素到数组末尾
- `pop`：删除数组末尾元素
- `shift`：删除数组首元素
- `unshift`：添加元素到数组开头
- `splice`：删除和插入元素
- `sort`：排序数组
- `reverse`：反转数组
- `fill`：填充数组

### 4.2 注释同步规则
- **push**：添加元素不影响现有注释，新元素无注释
- **pop**：删除末尾元素时同时删除对应注释
- **shift**：删除首元素注释，其余注释前移
- **unshift**：所有注释后移，新位置无注释
- **splice**：根据删除/插入操作移动或删除注释
- **sort**：注释跟随元素移动位置
- **reverse**：注释顺序反转，跟随对应元素
- **fill**：填充范围内的注释被清除

### 4.3 注释路径映射
- **路径格式**：使用点分路径 `"arr.0.1"` 表示数组嵌套路径
- **路径解析**：通过 `split('.')` 转换为路径数组
- **动态同步**：数组操作时动态更新注释映射

## 5. API使用规则

### 5.1 核心类方法
```typescript
// 解析JSONPC文本
const jpc = new JSONPC(text);

// 注释操作
jpc.setComments('path.to.prop', ['comment line 1', 'comment line 2']);
const comments = jpc.getComments('path.to.prop');

// 数据操作
jpc.set('path.to.prop', value);
const value = jpc.get('path.to.prop', defaultValue);

// 数组操作
jpc.updateArray('arr', 'push', [newValue]);

// 序列化
const jsonpcText = jpc.stringify();
const cleanJson = jpc.stringifyWithoutComment();
const cleanObj = jpc.toObject();
```

### 5.2 路径约定
- **使用点分路径**：`"a.b.c.0.1"` 表示嵌套属性路径
- **数组索引**：数组索引作为数字路径元素
- **路径解析**：内部通过 `split('.')` 转换为路径数组

## 6. 实现约束和限制

### 6.1 当前限制
- **只支持 `//` 注释**：不支持 `/* */` 块注释
- **注释位置固定**：只能在属性名正上方
- **格式重新生成**：序列化时会重新格式化，不保留原始格式
- **字符串内容**：字符串字面量内不能包含注释

### 6.2 性能考虑
- **UUID生成**：解析时为有注释的属性生成UUID，有性能开销
- **深度遍历**：解析和序列化都需要深度遍历数据结构
- **内存映射**：维护PathMap需要额外内存

## 7. 错误处理规则

### 7.1 解析错误
- **无效JSON**：去除注释后的JSON必须有效
- **注释位置**：注释必须在属性名正上方
- **格式错误**：属性名解析失败会抛出错误

### 7.2 操作错误
- **类型检查**：数组操作时会检查目标是否为数组
- **路径验证**：访问不存在的路径返回undefined或默认值
- **参数验证**：设置注释时验证参数类型

## 8. 扩展性考虑

### 8.1 多语言移植要点
- **核心算法**：PathMap、注释聚合、UUID标记机制可复用
- **数据结构**：路径映射和注释存储逻辑语言无关
- **序列化逻辑**：格式化输出需要适配各语言特性

### 8.2 标准化接口
- **统一API**：各语言版本应提供一致的API接口
- **路径格式**：使用统一的路径格式约定
- **行为一致**：确保所有语言版本行为完全一致
