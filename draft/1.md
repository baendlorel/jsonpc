## 1. `core/common.ts` — `_noop` 可内联

**现状：** `_noop` 函数仅被 `walker.class.ts` 用作默认 handler。

```typescript
// common.ts
export const _noop = () => {};
```

```typescript
// walker.class.ts
this.onComma = handlers.onComma ?? _noop;
this.onColon = handlers.onColon ?? _noop;
// ... 8 处引用
```

**建议：** 直接删除 `_noop` 导出，在 `walker.class.ts` 中定义局部 `_noop`（或直接内联 `() => {}`）。

**节约：** 删除 1 个导出，减少 `common.ts` 的公共 API 面。

## 2. `core/walker.class.ts` — 接口与类字段重复声明

**现状：** `WalkerOptions` 接口中的每个 handler 都在 `Walker` 类中重新声明一遍，且类型完全照搬：

```typescript
interface WalkerOptions {
  onComma: (args: WalkerHandlerArgs, stop: () => void) => void;
  onColon: (args: WalkerHandlerArgs, stop: () => void) => void;
  // ...
}

export class Walker {
  onComma: WalkerOptions['onComma'];  // 冗余
  onColon: WalkerOptions['onColon'];  // 冗余
  // ...
  constructor(text: string, handlers: Partial<WalkerOptions>) {
    this.onComma = handlers.onComma ?? _noop;
    this.onColon = handlers.onColon ?? _noop;
    // ...
  }
}
```

**建议：** 使用 `Pick<Required<WalkerOptions>, 'onComma' | 'onColon' | ...>` + `implements` 或直接删除接口，用类字段的类型推断替代。或者将 `Partial<WalkerOptions>` 参数直接解构赋值，合并声明与赋值。

另外，`stop` 闭包每次 `new Walker` 都重新创建：

```typescript
private stop = () => (this.end = NaN);
```

改用原型方法可以减少闭包开销：

```typescript
private stop() { this.end = NaN; }
```

## 3. `walkers/trailing-comma.ts` 与 `interpret-name.ts` — 重复的可变顶层变量模式

两个 walker 文件用了几乎完全相同的「顶层可变变量重置」模式：

```typescript
// trailing-comma.ts
let lastCommaIndex = -1;
let chars: (string | null)[] = [];
let state: WalkState = WalkState.Idle;

export function stripTrailingCommas(text: string) {
  chars = [];
  state = WalkState.Idle;
  lastCommaIndex = -1;
  stripTrailingCommasWalker.reset({ text }).run();
  const result = chars.filter((c) => c !== null).join('');
  return result;
}
```

```typescript
// interpret-name.ts
let chars: string[] = [];
let state: WalkState = WalkState.Idle;

export function interpretName(line: string) {
  chars = [];
  state = WalkState.Idle;
  interpretNameWalker.reset({ text: line, start: 1, inString: true }).run();
  // ...
  return chars.join('');
}
```

**建议（方案 A — 推荐）：** 改为函数内局部变量 + 通过 `afterChar`/`onStringContent` 回调收集结果，避免外部可变状态。如果担心 Walker 只能通过闭包捕获变量，定义一个类似 `createCollectorWalker(text, handlers)` 的工厂函数来封装此模式。

**建议（方案 B — 轻量）：** 提取一个通用 `resetState()` 辅助函数，但并不能消除顶层可变状态的根本问题。

## 4. `core/array.ts` — `shift`/`unshift`/`splice`/`reverse` 的 comments 操作模式重复

这四个函数都反复出现 `_move(commentsMap, from, to)` 和 `_delete(commentsMap, path)`。其中 `shift` 和 `unshift` 是对称操作，`splice` 最复杂但本质上也是「先删后移再删」。

例如 `shift` 与 `unshift` 核心逻辑结构对称但相反：

```
shift:  从 0 → lastIndex-1 向前挪动评论索引
unshift: 从 lastIndex-1 → 0 向后挪动评论索引
```

**建议：** 抽出一个 `shiftComments(map, path, start, offset, length)` 的辅助函数，统一处理四种操作的评论索引迁移。如果考虑内联优先且逻辑只有 2 处类似，则暂不抽取（遵守「相同逻辑少于 3 次不抽象」原则）。但这里**恰好 4 次**，值得抽象。

## 5. `core/initializers.ts` — `visit` 函数的重复分支模式

`visit` 函数的 4 个分支（uuid key / array / object / primitive）中，`_set(commentMap, nextPath, ...)` 和递归调用 `visit(...)` 重复出现：

```typescript
if (origin) {
  delete o[k];
  const nextPath = path.concat(origin);
  _set(commentMap, nextPath, v);
  if (typeof v === 'object') {
    visit(v, unames, nextPath, commentMap);
  }
} else if (_isArray(v)) {
  const arr: any[] = [];
  const nextPath = path.concat(k);
  _set(commentMap, nextPath, arr);
  for (let i = 0; i < v.length; i++) {
    visit(v[i], unames, nextPath.concat(String(i)), commentMap);
  }
}
```

**建议：** 将 `_set(commentMap, nextPath, ...)` 统一前置，减少重复。array 分支的 `arr: any[] = []` 似乎只创建了一个空数组然后从未使用（`commentMap` 中存的是 `v[i]` 的递归结果？），这里可能是个 bug 或死代码。

## 6. `core/initializers.ts` — `aggregate` 中的多余变量

```typescript
export function aggregate(lines: string[]): Array<string | string[]> {
  const modified: Array<string | string[]> = [];
  let array: string[] = [];   // ← 每次循环都会重置，初始值从未使用
  for (let i = 0; i < lines.length; i++) {
    if (_notComment(lines[i])) {
      array = [];             // ← 重置
      modified.push(lines[i]);
    } else {
      if (array.length === 0) {
        modified.push(array);
      }
      array.push(stripPrefix(lines[i]));
    }
  }
  return modified;
}
```

`let array: string[] = []` 的初始空数组实际上从未被使用（因为循环第一行非注释行就会 `array = []` 覆盖）。可以改成 `let array!: string[]` 或延迟初始化。

## 7. `index.ts` — 顶层函数可内联

`parse` 函数只是 `new JSONPC(...)` 的包装：

```typescript
export function parse(text: string, reviver?): JSONPC {
  return new JSONPC(text, reviver);
}
```

**建议：** 如果只在外部作为 API 入口，保留也可接受。但 `stringify` 有两个重载但最终只调用了 `jsonpc.stringify(...)`，也可以直接让用户调用实例方法，减少公共 API 面。

另外 `COMMENT_PREFIX` 的全局声明：

```typescript
if (typeof COMMENT_PREFIX === 'undefined') {
  (globalThis as any).COMMENT_PREFIX = '//';
}
```

这里 `COMMENT_PREFIX` 既是 `global.d.ts` 中声明的全局常量，又在运行时检查。如果打包工具能保证注入，这个兜底可以删除。

## 9. `index.ts` — `destroy()` 的释放写法

```typescript
destroy() {
  this.top.length = 0;
  this.bottom.length = 0;
  this.comments.clear();
  this.top = null as any;
  this.bottom = null as any;
  this.data = null as any;
  this.comments = null as any;
}
```

先清空再赋 `null`，`top.length = 0` 后紧接着 `top = null` 让前面的清空操作无效。可以直接赋 `null`。
